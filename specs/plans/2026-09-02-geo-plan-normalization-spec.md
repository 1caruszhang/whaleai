# Spec：GeoOperation 计划归一与思考冲突消除

> 状态：ready-for-agent（2026-09-02 五轮三方论证收敛版）
> 关联领域文档：`specs/tech_docs/geo_operations.md`、`specs/tech_docs/material_import.md`、`specs/tech_docs/system_prompt_architecture.md`（实现后回写）

## Problem Statement

用户在起点推导中明确选择「开新一轮（不更新品牌知识）」并放行计划后，操作仍从「收集品牌材料」步骤开始，并永久卡死在那里：用户在聊天里回复「跳过」无效，模型指引用户去点材料请求卡上一个不存在的「跳过」按钮（两次幻觉指引实测在案）。与此同时，主 Agent 的思考过程异常漫长：单个思考块最高 105,230 字符（约 6 分半纯权衡），一轮 6 条消息耗时约 35 分钟，可见正文合计仅约 400 字符。品牌工作区里已累积 3 个卡死在材料收集步骤的操作（跨 3 个会话），无人能推进。

## Solution

选了「不更新知识」的轮次，计划直接从「从问题池选择」开始，与用户在起点推导里的回答一致；「更新知识」的轮次按 next-step 信封指引收到材料请求卡，模型不再在调用现场重新盘问品牌知识是否够用；材料请求卡上有真实的「跳过材料收集」按钮，跳过后操作自动续接到下一步；主 Agent 的推理强度降档且冲突场景被协议消灭，思考恢复简短；跨会话的品牌摘要能看出每个未完成轮次是否更新了知识。

## User Stories

1. 作为 GEO 用户，我选「开新一轮、不更新知识」并放行计划后，计划的第一步就是从问题池选择，这样我不会被拖回材料收集。
2. 作为 GEO 用户，我选「全量重来 / 更新知识」后，走到材料步骤时按信封指引收到材料请求卡，模型不犹豫、不二次权衡。
3. 作为 GEO 用户，我在材料请求卡上能点「跳过材料收集」，跳过后流程自动进入下一步，不再死锁。
4. 作为 GEO 用户，模型不再指引进聊天或卡片上点任何不存在的按钮。
5. 作为 GEO 用户，一轮操作在可接受的时间内推进（不再出现 6 条消息 35 分钟的会话）。
6. 作为 GEO 用户，卡片上的时间戳语义真实（生成中 / 完成时刻），不误导。
7. 作为主 Agent（小静），我创建操作时传「全链意图 + 不更新知识」的组合会得到从问题池开始的计划，我不需要记住换意图枚举——协议对语义明确的组合有确定行为。
8. 作为主 Agent，我收到材料收集步骤的 next-step 信封时按计划调用即可；「知识够不够」的判断只在起点推导时发生一次，由计划形状承载。
9. 作为主 Agent，我在计划外顺序调用有后果的阶段工具时，收到结构化的指路拒绝（当前步 + 应调工具 + 一句话指引），一次读明白、一次重试到位，不需要自行恢复。
10. 作为主 Agent，我没有操作时的 freestyle 阶段调用被拒绝并指路先建操作，真实 Provider 花费不绕过计划纪律。
11. 作为主 Agent，我的推理强度已降档且指令冲突已消灭，冲突权衡不再发生；思考质量由真实场景回归验证。
12. 作为下一个会话的主 Agent，我在品牌摘要的未完成轮次条目里能看到该轮是否更新知识，起点推导不失真。
13. 作为下一个会话的主 Agent，我接管一个停在问题门的正确形状轮次后，用户在复用停卡重选卡上的确认能真实放行状态机（确认门步骤处于等待确认状态，里程碑推得动）。
14. 作为维护者，我能用步骤形状快照锁住「两个入口、同一计划形状」，防止意图与计划再次漂移。
15. 作为维护者，材料触发话术三处同源（工具描述 / next-step 引述 / 系统提示词），改一处全改，由集成测试断言一致。
16. 作为维护者，能力目录的主 Agent 推理强度展示值直接引用策略表，不再出现展示值与生效值漂移。
17. 作为运营，卡死的存量操作有明确清理路径，且留有一个真实轮次作为跨会话接管的端到端验收样本。

## Implementation Decisions

1. **计划组装归一（核心）**：全链意图携带「不更新知识」时，生成与「下一轮优化 + 不更新知识」完全相同的步骤形状——起点为问题段、首工作步为「从问题池选择」；两个意图分支消费同一份构造，杜绝双入口漂移。未携带或为真时保持全链现状（对既有调用方零破坏）。
   *否决备选：fail-loud 拒绝该组合。*理由（四条，均有代码与转录实证）：(a) 工具描述与系统提示词的两句话已在教模型产出该组合，服务端拒绝等于拒绝执行自家协议文本，不自洽；(b) 意图枚举到计划形状本就参数化（下一轮优化自身有两种形状），拒绝只挡住一个入口、语义对称污染仍在；(c) 错误往返本身是一次模型思考回合，实测同类回合 5–8 分钟；(d) 与「协议侧确定化、消灭现场裁量」的既有决策原则（ADR-0011 系）方向一致——归一让模型的自然行为直接产出正确结果。
2. **材料触发话术单源化**：新增材料收集契约常量，三处逐字同源（工具描述、next-step 单表 guidance、系统提示词材料段），模式对齐问题池复用契约。触发条件中「品牌无已确认知识或知识明显撑不起目标」的现场限定词删除，改为「计划放行后执行到材料收集步骤即调用」；知识充分性判断收敛到起点推导（其结果决定计划是否含材料步骤），薄知识场景的兜底走知识确认卡的 AI 补全行（既有机制）。此修复同时拆除「更新知识」轮次的同型冲突（品牌有确认知识但明确要更新时，信封与工具描述同样打架）。
3. **updateKnowledge 持久化**：进入操作投影与跨会话未完成轮次摘要（TS 类型、Rust 请求白名单、计划替换动作的往返三处同步），彻底消解意图标签的统计歧义。
4. **顺序校验闸**：五个有后果的阶段工具（问题池、内容计划、文章生成、分发计划、发布预览）入口校验「本会话非终态操作的当前步骤」——非当前步的阶段调用被拒，拒绝信封复用 next-step 引述结构（当前步 + 工具 + 指引），不造新机制。只读查询不闸（保护「先重读操作状态」纪律畅通）；材料类工具不闸（计划外补材料是合法入口）；查找用所有权感知口径（接管后操作归新会话，不得误拒认领来的操作）；无操作时拒绝并指路先建操作。
5. **跳过出口**：材料请求卡新增「跳过材料收集」动作（二次确认防误触），服务端走既有的计划替换动作剥离知识段剩余步骤，并发决策回执信封唤醒 Agent——整条链路复用「知识分支决策」已走通的机制。*否决备选：新增里程碑。*理由：里程碑推进器的确认门放行只作用于「等待确认」状态的步骤，够不着被前置步骤挡住的等待门，跳过场景下状态机推不动。
6. **止血：推理强度降档**：主 Agent 策略表推理强度降为 low；能力目录的主 Agent 展示条目改为引用策略表值（消双源，而非改字面值）。降档后以真实场景验证决策质量，不合格回调。
7. **系统提示词核对**（增量趋近于零，主要是与归一语义对齐）：意图决策表补「选定开新一轮 → 创建时显式带不更新知识」的首选路径表述；「继续上轮」选项到接管动作的映射措辞强化（实测断裂在案）；起点推导询问在「通信默认告知」条款中列为显式例外。
8. **存量处置**：取消三具卡死轮（fa450460、f74ce69e 会话各一、NULL 1b44fd12）；NULL 0cada786（下一轮优化正确形状、停在问题门、无主）**保留不取消**，作为跨会话接管的端到端验收样本。
9. **卡片时间戳语义**：交互卡片的完成时刻显示真实语义（生成中 / 完成时刻），与「跳过出口」同属「产品承诺了 UI 兑现」主题。

## Testing Decisions

- **原则**：只测外部行为——计划形状、信封引述、拒绝文案、状态机推进；不测实现内部结构。
- **计划组装快照（步骤形状锁定，非逐字节——意图与目标字段必然不同）**：三件套——全链+不更新 ≡ 下一轮+不更新（步骤序列的 id/标题/能力/确认门/初始状态完全相等，首工作步为从问题池选择）；全链+未携带 ≡ 现状全链（防回归）；非法跨度组合照旧 fail-loud。
- **next-step 单表**：条目存在性断言——「从问题池选择」必须有引述条目且 guidance 与复用契约同源（此前凭片段阅读误断缺失，靠测试钉死）。
- **话术单源**：参照问题池复用契约的 MCP 集成测试先例，断言三处逐字一致。
- **顺序校验**：越序调用被拒、拒绝信封含指路、接管后不误拒、无操作 freestyle 被拒并指路。
- **跳过出口**：卡片动作 → 计划替换 → 信封 → 状态机续接全链；跳过后下一信封引述正确步骤。
- **端到端验收样本**：接管存量 0cada786 轮走全链（起点推导推荐接管 → 接管 → 信封引述 → 复用停卡重选 → 用户确认 → 确认门放行）。
- **降档质量回归**：问题池选择与文章生成参数决策各跑两轮真实场景，比对决策质量。

## Out of Scope

- next-step 全表 guidance 铺设：观察单源化落地后的转录权衡热点再定，避免用今天的成本买假想的确定性。
- 发布预览单条删除/取消的模型侧能力（ba3b597a 会话实测暴露，用户侧「不点即弃」可用，归后续批次）。
- 思考内容前端二级截断（可选体验项，未排期）。
- 推理强度回调决策（视质量回归结果另行裁定）。
- DeepSeek 端点 budget_tokens 支持（未文档化行为，不依赖；effort 是唯一确认有效的旋钮）。
- 意图枚举重构（如显式起点段参数）：封闭组合归一已闭环，枚举膨胀无对等收益。

## Further Notes

- **方法论规矩（本次三方互驳沉淀，长期有效）**：停靠点断言一律以操作状态机的步骤持久层为准；模型正文叙事与状态机可以合法分叉，会话转录对状态无权威性；协议对语义明确的参数组合必须定义确定行为——归一优于拒绝，拒绝只用于逻辑矛盾与信息不足。
- **证据链摘要**：单块 105,230 字符思考含 48 次 "Let me reconsider"；「全链+不更新」组合两轮实锤（fa450460、f74ce69e）；DB 三具材料收集死锁；工具描述两句连读即教模型产出该组合。
- **票依赖骨架（供拆票）**：止血独立先行 → 归一 →（持久化、快照依赖归一）→ 顺序闸依赖归一 → 提示词核对依赖归一+单源化 → 跳过出口+时间戳依赖提示词核对 → 存量取消独立随时；0cada786 验收在跳过出口合入后执行。
