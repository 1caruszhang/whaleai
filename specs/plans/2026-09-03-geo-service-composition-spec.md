# Spec：GEO 领域服务组合根单源化

> 状态：已实现（2026-09-03 票 A＝9c049c4、票 B＝b36f92b 合入；验收全量测试绿：unit 1197 / dom 551 / integration 153）· 原 ready-for-agent（架构评审 + grilling 三轮收敛版）
> 关联领域文档：`specs/tech_docs/geo_provider_capabilities.md`、`specs/tech_docs/material_import.md`、`specs/tech_docs/geo_operations.md`（实现后回写）
> 来源：架构评审候选 1（浅模块判定 + 删除测试评估见当次评审记录）

## Problem Statement

五个 GEO 领域服务（材料导入、问题池、内容计划、文章生成、分发计划）的组装代码散在五处，各自携带微小变异：MCP 工具层按「会话+token 指纹」缓存并使用请求级账号 token；HTTP 面板路由按「会话」缓存并使用 sidecar 启动时捕获的 env token；闸门修订既不用请求级 token 也不接计费通道；后台导入队列与图片重扫各自手工构造材料导入服务。变异已经产出过一次线上事故（2026-08-31：MCP 构造点漏传配图候选池，Agent 批量生成与重生成全部静默零配图，单测全绿——bug 不在任何领域模块里，而在组装缝上），且 env token 口径是已修过一次的 401 事故族（6594d58）尚未闭合的同类隐患：sidecar 长跑数小时后 env token 过期，长会话的面板卡片操作与闸门修订仍依赖它调用网关。

对维护者：给服务加一个构造参数要同步改三到五处，漏一处即行为分裂且无测试可拦。对用户：同一个动作（例如文章重生成）走聊天和走面板可能在配图、计费、成败上表现不一致；长会话下面板路径存在既定的 401 风险。

## Solution

组装收敛为单一组合根模块：一个入口函数接收会话身份与少量场景选项，返回整族领域服务；能力捕获、token 口径、实例缓存、配图候选池注入、计费通道选择全部收进组合根的实现。五个组装点全部改为向组合根取服务，「调用方自己 new」绝迹。分两张票交付：先做行为零变化的等价搬家（现有变异按现状保留，仅收拢构造代码），再做 token 口径统一（面板路由与闸门修订接请求级新鲜 token，闭合 env-token 过期隐患）。闸门修订「不计费」从看似遗漏升级为显式裁决参数。

## User Stories

1. 作为 GEO 用户，我在长会话（数小时）里从面板卡片发起的确认、重试、重生成不再因为 sidecar 启动时的 token 过期而 401 失败。
2. 作为 GEO 用户，我在聊天里对闸门未决内容下达修订指令后触发的重生成，同样不依赖过期 token，长会话修订不再中途 material_billing_failed。
3. 作为 GEO 用户，同一篇文章的重生成无论从聊天（Agent）、面板（HTTP）还是闸门修订进入，配图候选池、计费口径、领域语义完全一致——路径不再决定结果。
4. 作为 GEO 用户，2026-08-31 那类「某条路径静默零配图」的事故由回归测试直接钉死，同类组装漏参在合入前变红。
5. 作为主 Agent（小静），我经 MCP 调用的领域服务与面板/卡片走的是同一构造保证的实例族——「工具与面板同一领域语义」从注释自觉变为构造事实。
6. 作为维护者，我给某个领域服务增加构造参数（新能力、新端口）时只改组合根一处，五类消费方自动同口径，不存在「记得同步第三处」。
7. 作为维护者，我新增一个领域服务时只有一个出生点可选，不可能在某个调用方私建变体。
8. 作为维护者，我想知道「这个服务用哪个 token、接不接计费、缓存多久」时，读组合根一个文件就有全部答案，不再需要在三个文件里比对变异。
9. 作为维护者，我调试组装问题时可以对着组合根的三个直接测试（实例复用、token 重建、池注入）定位，而不是在三条路径分别复现。
10. 作为测试作者，我替换能力层只需 mock 一个 provider-runtime 模块（仓库既有习惯），组合根的全部行为即可在进程内驱动，不需要起真 sidecar。
11. 作为下一个会话的贡献者，我读到 service-composition 模块就能理解服务的完整口径矩阵，不需要考古三处注释与两次事故的修复记录。
12. 作为 GEO 用户，闸门修订（对我已付费产物的修正迭代）保持不计费——这个口径被显式参数表达，未来若要变更必须走一次有意识的领域裁决，而不是某次重构的顺手副作用。

## Implementation Decisions

1. **组合根为独立新模块**（service-composition）：职责是「服务怎么组装」（能力＋端口＋计费＋缓存 → 服务）。与 provider-runtime 的「能力怎么造」（secrets → 能力）分层分开，各自保持深。*否决备选：塞进 provider-runtime*——两层职责不同，合并会让能力层接口变宽。
2. **接口形状＝服务包**：一个函数返回整族服务，调用方按需取字段。构造口径（token、缓存、池、计费）不是调用方须知，全部下沉为实现。*否决备选：逐服务 getter*——七个 getter 会把缓存管理留在接口外，等于没收敛（删除测试不过）。

   ```ts
   geoServices(identity: { workspaceId; sessionId }, options?: {
     accountToken?: string;
     billing?: 'default' | 'revision-unbilled';
     rescanBudgetMs?: number;
   }) => {
     materialImport; questionPool; topicPlan; article;
     distribution; baseline; publishPreview;
   }
   ```

3. **三个场景选项的语义**：`accountToken` 是请求级新鲜账号 token（Rust 代理附带、临期已刷新），缺省回退启动单例；`billing: 'revision-unbilled'` 显式表达闸门修订不计费的裁决；`rescanBudgetMs` 透传图片重扫的时间预算，且在场即按不计费口径构造材料导入服务（重扫从不接计费通道＝收敛前口径，与闸门修订同为 unbilled 构造；未来若要「带预算的计费导入」，必须先显式拆开这一耦合，不得默认沿用）。后台导入队列「入队时捕获 token」的场景语义保留——捕获时机在调用方，传值进组合根。
4. **能力与计费口径内部统一为请求级优先**：组合根内部一律走「请求级能力 getter（token 缺省回退单例）」与同口径的计费 permit 通道；开发直连模式（无网关基地址）行为不变。
5. **缓存策略**：问题池、内容计划、文章、分发、基线五服务按「工作区:会话:token 指纹」缓存（token 轮换即重建，旧 token 不留缓存闭包——该语义已在 MCP 组装点实现并有注释在案，推广到全量）；材料导入与发布预览端口不缓存（低频调用、场景参数各异/不走网关）。合入后事实修正（2026-09-03 code-review）：初稿曾写「不缓存＝现状即如此」——实际收敛前 MCP 侧发布预览有 runtime 缓存、闸门修订有按身份 Map 缓存，均随收敛移除；等价性依据是发布预览端口无状态、修订路径只调持久化面方法（revise/latest/saveItems/edit），逐次现构可观察行为不变（Decision 7 的「行为零变化」据此成立，而非「原本就不缓存」）。缓存键格式统一进第一张票——无 token 时指纹为空串，键退化为现状格式，等价性不受影响。
6. **文章服务三口径同接配图候选池**：MCP、HTTP、闸门修订三条路径的 articleService 均注入材料图片资产取数（ADR-0008 T4 口径）。2026-08-31 事故后三处已各自补上，本决策把它从三份自觉收敛为一份构造保证，并由回归测试钉死。
7. **两张票的边界**：票 A＝等价搬家——组合根落地，五处组装全部迁入，面板路由与闸门修订暂传 undefined token（回退单例＝现状），闸门修订带 revision-unbilled，rescan 预算透传，缓存键格式统一；验收＝现有全部测试绿＋行为零变化。票 B＝token 接入（阻塞于 A）——HTTP 路由的调用方从请求头提取 token 传入；闸门修订上下文（GateRevisionContext）增加 requestAccountToken 字段，由唯一入口 revise_gate_content 工具的 handler 从 MCP 会话上下文带入（已核实与 MCP 组装点同源可得）。
8. **闸门修订不计费为显式裁决而非遗漏**：以 billing 参数枚举值表达；若未来要给修订重生成计费，属用户可感知的花费行为变更，必须走独立领域裁决（届时可再议 ADR），不得夹带在任何重构票里。本次不建 ADR——补计费随时可加，不满足「难以逆转」。
9. **测试注入走模块 mock**：组合根测试沿用仓库既有习惯（mock provider-runtime 模块，先例：xiaojing-geo-tool 单测 18 处 mock）。*否决备选：接口加可选 capabilityFactory 参数*——会让接口为测试变宽（浅化）。
10. **词汇沉淀口径**：「组合根」「服务包」是架构词汇，不进 CONTEXT.md（那里只放领域词汇）；领域侧无新概念产生。

## Testing Decisions

- **原则**：只测组合根的外部可观察行为——实例复用与重建、能力口径、池注入、计费形态；不测内部构造顺序与私有结构。
- **票 A 新增组合根直测三条**：(1) 同一身份＋同一 token 重复取服务返回同一实例；(2) token 变化后返回重建实例（旧 token 不留缓存闭包）；(3) **三条路径（MCP／HTTP／闸门修订）的 articleService 均接通配图候选池**——2026-08-31 事故的直接回归钉，断言方式参照该事故的修复口径。合入后补强（2026-09-03 code-review）：(3) 的 HTTP 腿原只以组合根 options 等价覆盖，另在 `xiaojing-panel-request-token.integration.test.ts` 增设真实路由级钉（`articles/latest` 经真实路由→组合根构造，构造边界断言池接通材料图片资产）。
- **等价性验收**：票 A 合入前后，现有全部 TS 单测与集成测试结果一致（绿→绿）；Rust 侧不涉及本变更。
- **票 B 新增**：面板路径与闸门修订路径的服务持有请求级 token（经 mock 能力层断言网关调用携带的 token 来自请求而非 env 单例）；无请求 token 时回退单例的行为有断言。
- **先例参照**：provider-runtime 的模块 mock 习惯（xiaojing-geo-tool.unit.test.ts）；「三处同源＋集成测试钉逐字一致」的材料契约/问题池复用契约模式（本 spec 的回归钉同族）。

## Out of Scope

- 闸门修订补计费（用户可感知的花费变更，独立领域裁决）。
- provider 全局 getter 的彻底消灭——「token 缺省回退单例」的兜底语义保留（开发直连与无头场景依赖）。
- 架构评审其余候选（跨语言契约 pin、顺序闸上移、管理端路由表、轮询刷新统一、提示词纪律单源、竞品名单深模块、material-import 六职责拆分等）——各自独立成案。
- 服务内部实现的任何行为调整（票 A 的等价性红线）。

## Further Notes

- **票依赖骨架（供拆票）**：票 A（等价搬家）→ 票 B（token 接入）；票 B 内面板路由与闸门修订两个接入点互相独立、可分合入。
- **变异矩阵存档（收敛前现状，验收对照用）**：MCP 组装点＝指纹缓存＋请求级能力＋请求级计费；HTTP 面板路由＝会话缓存＋全局能力＋全局计费；闸门修订＝Map 缓存＋全局能力＋无计费；后台导入＝不缓存＋入队捕获 token＋请求级计费；图片重扫＝不缓存＋请求头 token＋无计费（rescan 预算参数）。
- **证据链摘要**：零配图事故的三处修复注释在案（xiaojing-geo-tool / xiaojing-shared / gate-revision，均注明 2026-08-31）；env token 过期隐患由 provider-runtime 注释自证（「Sidecar 长跑数小时后 env token 早已过期……必须以请求级 token 为准」）＋ 6594d58 前科（env token 约 15 分钟过期致长会话面板导入/重试 401）。
- **事实修正记录**：架构评审初版曾表述「统一后 MCP 路径恢复配图」——grilling 读码核实零配图事故已修复，本 spec 处置的是「该类组装漏参的构造性预防＋env token 隐患闭合」，非现行缺陷修复。合入后 code-review 修正（2026-09-03）：Decision 5 的「不缓存＝现状即如此」与事实不符（收敛前 MCP 发布预览有 runtime 缓存、闸门修订有 Map 缓存），已在 Decision 5 改口为「随收敛移除＋无状态等价论证」；`geo_operations.md` 回写中「私建领域服务在全仓绝迹」收窄为「该七服务族绝迹」（`xiaojing-effects.ts` 的家族外服务不在收敛范围）；三域路由文件的 token 提取与传参收敛为 `xiaojing-shared.ts::geoServicesForRequest` 单源（原逐文件复制）。
