# 竞品名单真实性与竞品内容生成

决策依据：ADR 0007。本文是该 ADR 的执行细则与改动清单。v1 采用最小结构（见「显式延后」），本文件描述 v1 口径。

## 背景与病灶

竞品链路的三类真实事故（2026-08 复盘）：

1. **幻觉品牌**：联网富化是合并式调用（`provider-capabilities.ts:782-822`，ARK `enable_search`），返回值只解析 `choices[0].message.content`——模型最终文本，检索过程与引用不返回也不可验证；候选的 `sourceExcerpt` 是模型自写摘要而非检索原文。用户事后人工搜索查无此牌。
2. **错域品牌**：查询词用裸 `serviceArea` 字符串拼接（`material-import.ts:1159-1182`），未接地域锚模块；候选 `region` 仅查非空+截 40 字符（`material-import.ts:548-559`），从不与品牌服务范围比对。serviceArea 缺失时查询退化为「行业+排行榜」全国形态，武汉/长沙的榜文品牌直接进卡。问题池/选题/文章三条链均已消费 `deriveServiceScope`，唯独竞品链未接。
3. **确认后不可纠错**：批量确认卡无逐行删除（`reject-candidate` 在 `knowledgeCard.ts:19-23` 存在但从不发出）；任何字段确认后三层（UI/management API/数据层）均无修订入口（`management_api.rs:84-103` 仅五路由，`knowledge.rs` 无 `DELETE FROM`）。竞品是数组字段走合并语义永不出「二选一」（`knowledge-authority.ts:340-362`），看似只能确认。

结构性诱因：排行榜硬性要求 ≥5 家已确认竞品（`articleGeneration.ts:396-401`）而富化目标 10 家，凑数压力与「宁缺毋滥」天然打架；查询品牌名用 Rust 工作区名而非知识库裁决名（`materials.rs:130-141` vs `profileInjection.ts:185-194`）。

另有一个文章侧既有缺陷：排行 prompt 只注入名单名称（`articleGeneration.ts:460-465`），「唯一 Claim 根基」只含目标品牌事实，而格式契约要求竞品条目「每条必须是具体的经营信息、禁占位、禁空话」（`articleGeneration.ts:190-199`）——对竞品条目构成结构性强制编造。

## 设计总纲（用户裁定）

**名单层求真（硬，代码保证）；内容层尽力（软，联网取材）；全程零新增主动询问；v1 最小结构。**

- 知识确认卡上的竞品字段**必须真实且准确**——唯一硬要求，由确定性代码保证，不再依赖提示词自律。
- 文章竞品内容**尽可能准确即可**——排行类型生成整篇联网（用户明示选择，接受目标品牌段落可能被网络内容渗透的风险，ADR 0007 Decision 4）。
- 所有信息只出现在用户本来就要看的面（确认卡/聊天），不新增任何主动问询。
- 实现最小化：无 schema 变更、无新表、无新后端路由；防御性加固（阶梯、懒清洗、面板入口）全部延后，见「显式延后」。

## 导入侧：单腿「取名于真实检索」

`enrichCompetitors`（`material-import.ts:1056-1251`）重写为**源锚定抽取**结构，与材料腿哲学对称（材料腿=从真实材料文本抽取+逐字证据门；联网腿=从真实搜索结果抽取+逐字证据门）：

```text
① searchSources × 2 次，并行（豆包搜索 HTTP API，纯结构化召回 Title/Summary/Url，
   不经 LLM 改写，免费额度）。查询词优先用材料抽取时模型以【目标客户口吻】
   顺手产出的 competitorSearchQueries（经营者→「地域+品类/项目+加盟/合作」；
   终端消费者→「地域+品类+排行榜/哪家好」——客户视角由模型读材料判定，
   代码零行业词，用户裁决 2026-08-30「一劳永逸」版；两条必须分池互补：第 1 条
   客户口吻需求问句型（…哪家好/怎么选），第 2 条中立观察者品类盘点型
   （…品牌有哪些/盘点）且禁带加盟/招商/合作词——观察者口吻才命中品类
   分析文/本地探店/多品牌列表页，两条同池困在单一投放软文池（余美娟缺席
   回归 2026-08-31，升级自「1+2」裁决））；抽取未产出时
   回落「{主锚+产品赛道} 排行榜 / 哪家好」默认形态。语料合并后先按 URL
   去重、再按可注册域封顶（每域最多 3 条保检索序——张仔纪霸屏回归：40 条
   源 19/20 来自 4 个软文站；域名键剥 www./m. 前缀与子域，com.cn 等两段
   公共后缀取倒数三段）
② 一次普通 LLM 抽取调用（extraction 槽，如 DeepSeek，不联网）：
   输入=①的全部快照；输出两层名单 {direct, potential}，每家 {name, region}
   （direct=三同全中的直接竞品；potential=抢同一批客户但三同缺一角的潜在竞品，
    判不准归 potential 宁低勿高；继承既有提示词纪律：同层级/同赛道/前东家排除/
    上下游排除/自名与形近排除/已知竞品去重）
③ 本地字符串校验（零 API 调用），两层同闸：
   - 存在校：name 归一化后逐字出现在其所引快照里，否则丢弃
   - 地域闸（仅城市/区县锚）：region 归一化后命中白名单，否则丢弃
   - 关系闸：所引快照里名字附近出现供应/合作/前东家等非竞争关系词的丢弃
     （沿用既有 NON_COMPETITOR_RELATION 词表，从「摘录门」迁移为「快照门」）
   - 跨层互斥：与直接层归一名相等或互为子串的潜在名丢弃（张仔纪/张纪仔不留双份）
   - 层内互斥：同口径（顺德杨廷记餐饮有限公司/顺德杨廷记只留先出现的一份）
   - 名字净化：繁体源页名归简存储（榕邊→榕边，存在闸比对两侧同映射）；
     「·」首段归一（·后是软文自造的产品线尾巴，取·前主品牌段——同品牌
     马甲同核后层内/跨层互斥自然生效）；引号包裹/「相关」句式的描述短语
     不是品牌名，剔除
④ 幸存者作为 inferred/0.5 候选走既有 propose → 确认卡（数据两个 fact：
   competitors + potentialCompetitors；卡面合并为单一「竞品」栏——直接层在前、
   潜在层带「潜在：」分界标记与补位小注，均逐项 ✕）。每行证据带命中源
   URL：「名（地域）：快照（来源：<url>）」，卡面展开渲染为可点击外链
```

要点：

- **存在性由构造保证**：名字从真实检索结果里长出来，不是模型记忆凭空生成；③的存在闸只是兜住抽取时的漏网幻觉，对已持有数据做字符串匹配，不发起任何 API 调用。
- **两步职责分离**：`searchSources` 是手（弄到真实语料），抽取是眼（从语料认名字）。品牌名是开放词汇（「留香卤坊」不在任何词典里），纯规则/分词无法从散文中识别，LLM 阅读是「机器读中文」的最小代价，且该调用读两路各 20 条短摘要（最多前 30 条进提示词）仅数千 token，是全链路最便宜的一笔，替代的恰是现状 3 次昂贵的 enable_search 合并调用——总账下降。
- **查询接线**：查询词优先模型产出（见①）；回落形态的查询品牌名用 `resolveBrandName`（知识库裁决名）、服务区用 `deriveCompetitorScope` 派生主锚（不再透传脏文本）。
- **语料多样性两闸（用户裁决 2026-08-31「1+2」）**：意图互补在提示词层（见①），域名封顶在代码层（`dedupeSourcesByUrl` → `capSourcesPerDomain`，`sourceDomainKey` 是共享层 `registeredDomain` 的薄适配——可注册域后缀清单与渠道召回侧同源一份，解析失败原样兜底）——单一品牌的 GEO 投放会把垂类搜索结果霸屏成同四站软文，把多品牌列表页挤出语料后抽取只剩一家可认。裁剪后的列表同源供给模型快照（前 30 条）与存在闸语料，两条腿看到同一份裁剪结果；cap 非正数时原样放行（纯函数，可单测）。
- **客户口径纪律（判别第 0 步）**：先从画像（目标客户/经营场景/核心优势已注入提示词）确定客户是谁；竞品=争夺同一批客户预算的对手，客户群不同的候选无论品类多相近两层都不进——炊班主（客户是创业者）的直接竞品是项目/加盟输出品牌，服务食客的同品类餐厅不是。**无锚（serviceArea 缺失或「全国/线上」类）时整轮富化跳过**，卡上以一行被动提示「材料未提供可定位的服务区域，竞品联网补全已跳过」，不追问。
- **地域锚粒度（2026-08-30 用户裁决）**：声明什么粒度锚什么粒度。城市/区县锚（成都新都）白名单字符串比对硬拦跨城；**省级锚（广东省/广西壮族自治区等）归一短名（广东/广西）直接拼进查询**——查询锚定本身是最强地域过滤，地域相关性由抽取模型自证，代码不做省→市映射；混合声明（广东省、长沙市）含省段即按省级宽口径处理。已接受残余风险：省级锚下偶有真实但外省品牌进卡，确认卡逐行删除兜底。
- **enable_search 合并式调用降级为兜底**：仅当 `searchSources` 不可用（无 key/调用失败/返回为空）时回落，回落路径同样过③的本地地域闸（存在闸在回落路径无快照可比，接受降级并保持 inferred 必审）。
- **≥5 家可用为目标**（缓冲 10 家不变）。闸门永不放水凑数；不足时卡上被动展示可用家数，编辑框既有能力可补名（用户点名走既有 `confirm_ranking_competitors` 窄通道）。不设检索阶梯重试——先观察固定 2 查询 + 闸门的存活率，不够再议（见显式延后）。
- **排行 roster 组装（ADR-0007 Decision 6，用户裁决 2026-08-30）**：直接层优先，不足 5 家用潜在层按序补足到 5——`resolveRankingRoster`（TS）与 `valid_ranking_competitors`（Rust，`articles.rs`）同构，契约用例共享 `rankingCompetitorContractCases.json`；跨层归一名嵌套互斥、身份/关联主体排除两层共用；标题红线名单（topic-plan）同步含两层。fail-closed 门槛按合并后计数（正文段 policyVersion v4→v5，invariants D15）。

### 元数据退役

`[[xiaojing-competitor-details:v1]]` 审计头（`competitorDetails.ts:36-47`）**停止新增编码**；读侧保留解码兼容存量展示。`KnowledgeBatchCard` 竞品行从「名称｜地域｜业务」胶囊简化为纯名称；region 不再作为结构化字段上卡或落库（similarBusiness 废弃）——仅作管线过滤变量；证据文本行「名（地域）：快照」中的地域表述随审计摘录留痕，供展开复核参考。

## 确认卡投影与逐行删除

- 竞品行只显示名称；**数组字段行（不只竞品）增加逐行 ✕ 删除**：点击即暂存「数组减一」，随整卡确认以 `adopt-edited` 提交（复用 `submitDecisions` 既有 decision 词表，`KnowledgeBatchCard.tsx:334-351`）。
- 过滤计数行（「已自动过滤：地域不符 X 条」）为**可选**一行文本，实现时顺手带上即可，不作为验收项。

## 确认后修订：聊天侧（零新后端）

修订语义 = **新提议 + 再裁决**（版本递增、全程留痕），全部复用既有机制：

- 用户在聊天中说「删掉竞品里的XX / 把XX改成YY」→ agent 走**现有** `propose_brand_fact` 提议新名单 → 既有确认卡出现 → 用户裁决，版本+1。
- 实现工作仅为**系统提示词补一条纪律**：已确认事实（含竞品名单）的修改必须经提议-裁决，不得口头直接宣布改完。
- 面板修订入口与专用路由**延后**（见显式延后）；聊天是本产品唯一 Agent 入口，路径今天已存在，缺的只是可发现性。

存量清理走同一通道：用户发现旧工作区有假竞品，聊天一句话修订名单，不做懒清洗模块。

## 文章侧：排行类型整篇联网（用户裁定，ADR 0007 Decision 4）

- **ranking 类型**文章的生成调用启用联网（`enable_search`，或路由至联网端点——若现行文章生成槽位模型不支持联网则切 ARK 联网端点，非排行类型不变）。
- 既有「只使用输入中列出的已批准事实」提示词纪律**原样保留**——它是目标品牌段落唯一的防线，属提示词层尽力约束。
- **已接受风险（用户明示）**：联网素材可能渗入目标品牌段落（如把招商软文数字织进品牌介绍）。工程侧推荐的「一次预取资料块 + 离线写作」方案被否决，理由是实现更简单；风险登记在 ADR 0007，若日后事故复现可按该 ADR 的 Considered Options 回切。
- 竞品条目既有「定性+品类描述为主、目标品牌信息密度写足」的编排纪律（`articleGeneration.ts:195`）保留，联网素材主要作用是消除名称级与事实级编造。

## 显式延后（用户裁定 v1 不做）

- **检索阶梯**（多轮变体重试直至 ≥5 家）：先观察固定 2 查询+双闸的存活率，大城市榜单语料大概率足够；不够再议加一轮重试。
- **知识面板修订入口 + propose-revision 专用路由**：聊天路径已可用，面板入口只提升可发现性。
- **存量懒清洗模块**（消费时静默复核、TTL 缓存、档案记录）：v1 用聊天修订手动清理；新导入已干净。
- **逐字段证据标注**（Measured/Estimated/N-A）、**维度后选**（先取料后选六维度）、**用户口头补充通道**、**薄资料处置机制**、**竞品别名字段**：全部不做。

## 验收

- 单测：抽取输出的名字未逐字出现在所引快照 → 被存在闸丢弃；region 不在城市/区县锚白名单 → 被地域闸丢弃；省级锚（广东省）不跳过、查询含省短名、深圳候选不被字符串闸拦；无锚时富化整体跳过且卡上出现提示行；逐行 ✕ 产出 adopt-edited 减一数组；enable_search 兜底路径在 searchSources 失败时接通且过地域闸。
- 回归：炊班长/炊事班形近变体测试（`material-import.unit.test.ts:1127-1213`）、材料腿逐字证据门（`:785-816`）不动；排行 <5 fail-closed 行为不变；现有断言「searchSources 不得被调用」的测试（`:827-850、880-900`）随设计翻转而改写。
