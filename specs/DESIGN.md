# 小鲸同学界面规范

## 产品结构

应用有四个一级入口：主聊天、品牌工作台（聊天右侧）、品牌档案与效果（左侧栏一级导航，主区整页）。主聊天是唯一 Agent 入口；品牌工作台是当前聚焦 GEO 操作的权威产物投影；品牌档案与效果是品牌级入口，跟随当前选中品牌、不依赖任何 Session。不要加入独立任务中心、全局搜索、通用扩展管理、终端、浏览器或悬浮入口。

## 布局

- 左侧栏：品牌选择、Session 列表、新建会话，以及「品牌档案」「效果」两个品牌级一级导航入口；左下角是「个人信息」入口（手机号/点数余额/充值引导/渠道分发点数上限/退出登录，票 06 账号化后替代原设置页）。渠道分发上限使用点数输入，默认单篇 `3000`、单次 `20000`，并明确提示仅影响之后创建的计划。
- 主区：聊天 Tab 内为聊天与右侧品牌工作台；品牌档案与效果为主区整页；欢迎页主区全宽，不挂工作台。未登录、宽限超期或首登未改密时整窗只呈现账号门（登录页/强制改密屏），工作台不挂载。
- 品牌工作台自上而下只有三段：多操作切换器（「目前所在阶段」跟随聚焦操作）→ 常驻当前已确认品牌知识面板 → 六阶段竖向手风琴骨架（当前阶段展开显示其产物面板，其余阶段收起为单行，点击可回看）。工作台产物面板全部只读，不含操作控制与编辑控件，不把一次操作包装成新的项目或工作流产品。各阶段面板只展示用户已确认的产物（已确认问题池的选定问题、已确认选题计划、已批准文章、已确认分发计划）；未确认的过程产物、草稿与失败细节只在聊天卡片呈现，面板以引导文案指向对应确认卡。
- 「品牌档案」整页只读呈现，无确认或动作入口。三层信息架构：第一层「当前档案」看板——最新已确认知识版本的事实按语义聚成 widget 网格（mono 微标签 + 细网格纹理 + tabular-nums 大数字，scoped 样式只挂在 `data-xiaojing-brand-archive` 子树，见 index.css `.ba-*`），来源证据默认隐藏、由卡片角落入口显式展开；第二层「版本历史」默认收起，每版一行摘要 + 与上一版的前端 diff（新增/移除/变更字段），展开只看 diff 详情；第三层「产物」按七类分组为 widget（类型中文名 + 数量 + 最新状态与时间），UUID/Operation/Session/revision 收进「技术详情」折叠，血缘简化为「基于知识 vN」。
- 「效果」整页承载真实数据效果看板、监测计划管理（显式启用门）与按需基线探测；启用监测前必须先冻结一次基线。看板自上而下为：一句话结论条（仅由真实数据确定性拼接，无数据如实标注不造句）→ KPI 卡（delta 徽章遵守两轮确认噪声纪律：单轮变化只标中性「观测波动」，连续两轮同向才标趋势色）→ 优化曲线（手写 SVG）→ 问题诊断矩阵（每题一行：五档诊断徽章「疑似负面/竞品主导/缺席/排名低/正常」+ 基线 → 最新轮 before/after 双值 + 趋势箭头；疑似负面是复核线索不是判决；失败题只标「失败」，不落入「缺席」）→ 证据/样本库（按题展开各轮原始回答、引用 URL 与解析依据，注明数字来源为真实基线探测与监测轮次）。页头「报告视图」切换渲染一页纸报告（品牌名 + 生成时间 + 结论条 + KPI + 诊断矩阵精简版 + 分题前后对照：每题一行「基线 → 最新轮」双值与命中率），配 `@media print` 浅色化打印样式，不做文件导出。看板只使用真实基线与监测证据，缺失时如实标注，不引入演示数据。真实投影（最新基线、监测计划与 run、最新发布执行）经 Rust IPC 免会话直读，未打开会话时页面照常渲染完整看板骨架与既有结果，仅基线探测、监测配置/启用/重试等执行类操作要求先打开该品牌的会话（顶部提示条引导）。
- 关键决策使用结构化卡片；长内容使用摘要和显式展开。

## 状态表达

- `loading`：已有确定请求正在执行。
- `empty`：权威数据源确实为空。
- `unavailable`：能力或 Provider 未配置，不能伪装为空数据。
- `failed`：请求失败并保留可诊断原因。
- `stale`：输入版本已变化，旧结果仍可查看但不能继续消费。

真实 GEO 数据缺失时显示“暂无真实数据”或明确的不可用原因，不生成占位指标、演示证据或虚构成功。

## 用户确认

以下动作必须由用户在结构化 UI 中确认：品牌事实变更、问题池/主题/分发计划确认、文章批准、付费发布、未知外部结果核对和不确定重试。按钮文案应说明动作与影响，危险或付费动作不能依赖聊天中的隐含同意。

## 信息闸门卡片

所有需要用户确认的步骤（知识裁决、问题池选择、选题确认、文章批准、分发确认等）一律使用聊天内**信息闸门卡片**，交互与位置以品牌知识确认卡（`KnowledgeBatchCard`）为参考实现：

- **位置**：卡片统一渲染在该条助手消息全部正文之后——用户先读结论，再操作；过程性工具行仍按原顺序折叠展示。
- **默认展开与按类分格**：知识确认卡按品牌档案字段分格（固定字段序、同类多值合并为一格），默认展开供快速扫读，摘要头仍可点击收起；正文为双列网格、每类一格——格内材料原文与已裁决候选带绿色「已就绪」徽章，推断/冲突/失败候选带黄色「待确认」徽章，两类可在同一格并存，行头给「已就绪 N / 待确认 N」摘要，含待确认内容的类排网格前部；卡片头部计数按类（「共 N 类信息 · M 类待确认」）而非候选条数；候选值以胶囊呈现、冲突胶囊内联「当前值 → 新值」对比，摘录与置信度收进行展开详情；正文限高内滚（`max-h-[60vh] overflow-y-auto`），所有卡片随聊天滚动，超长批次靠卡片自身滚轴浏览；整卡确认按钮常驻卡片头部（收起正文也可见），不藏在长列表底部。其余闸门卡片沿用摘要优先的折叠形态，除非采用同款字段行复核模式。
- **分层默认**（ADR 0003）：材料原文行（extracted/asked）视为已就绪、零控件；AI 补全行（inferred）只带纯视觉的逐行「确认」；冲突行必须显式「采用新值 / 保留当前值」，未全部解决前整卡确认禁用；被截断字段在行内提示「另有 N 条未展示」。整卡一次「确认」即全量采纳全部未决候选（含从未逐条查看的 AI 补全行；全为原文零冲突也必须点这一次确认）。
- **行内「更改」**：每一行（含原文、补全、冲突行）都可内联编辑值（数组值按顿号分隔多值输入，多候选行逐候选编辑并按 subject 区分 scope）。更改只按候选 id 暂存在卡片本地、不落库，暂存与逐行确认状态在 3 秒轮询重建后保留；被更改的候选徽章变「用户补充 · 已就绪」并不再出现确认/二选一控件，整卡确认时携带编辑值按 `adopt-edited` 提交，未改动的输入保持原裁决路径。
- **单一裁决入口**：卡片只提交结构化决策，不得组装第二套 prompt、启动第二个 Agent，或引导用户到其他界面寻找确认入口；已裁决条目在会话重载后按权威状态渲染结果，不重复给按钮。
- **边界**：付费发布的确认仍必须经 WebView 显式用户动作通道提交；聊天卡片上的按钮可以作为该显式动作，但不得绕过 Tauri IPC 的确认路由。

后续新增确认步骤必须沿用本节规范；聊天内的信息闸门卡片是唯一确认交互，工作台面板不承载任何确认入口，不并行出现两套确认交互。

## 视觉与可访问性

- 延续现有 CSS token 和字号层级，避免为单个页面建立第二套主题系统。唯一例外（2026-08-19 拍板）：品牌级「效果」整页采用 js_ai GeoDemoDashboard 风格的 scoped 深色看板主题（`index.css` 的 `.geo-dash-scope`，`--geo-dash-*` 变量只挂在该子树，不进入全局 Theme token、不响应全局 light/dark 切换）；在聊天/工作台内复用的基线与监测面板用同名变量的回退值保持既有浅色外观。新增看板变量（如疑似负面专用的 `--geo-dash-amber`）同样只加在 `.geo-dash-scope` 作用域内，不得把深色值内联进组件；报告视图的打印浅色化只在 `@media print` 内重定义同一组变量，组件零改动。
- 交互控件保留可见 focus 状态和键盘路径；图标按钮提供可访问名称。
- 颜色不作为状态的唯一载体；错误、阻断和版本失效同时给出文字。
- 窗口窄化时优先保持主任务可操作，次要详情折叠，不产生横向页面滚动。

## 通知与深链

桌面通知只用于用户不在当前窗口时的主聊天完成和 GEO 监测告警。点击后必须定位到精确目标：待确认门通知落到对应聊天 Tab 并定位到闸门卡，监测告警落到「效果」入口的具体监测 run；失效目标显示可理解的错误，不跳到相似对象。
