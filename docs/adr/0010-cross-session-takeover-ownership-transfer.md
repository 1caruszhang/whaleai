# 未完成 GEO 工作的跨会话接管：所有权转移模型

## Context

现行 session 私有条款（geo_operations spec：跨 Session 只共享已确认产物，`awaiting-selection`、draft、未全部批准的 article operation 等未批准状态留在创建 Session）导致：一轮优化中途换会话（关窗重开、换设备），未完成工作即搁浅——草稿审到一半、待选池没选完，新会话看不到也接不了，只能整轮重开。

2026-09-01 设计对谈（grill-with-docs）收敛的需求：新会话说「帮我做 GEO 优化」，agent 读取品牌状态后识别已完成/未完成，带推荐选项询问（继续上轮 / 开新一轮不更新知识 / 全量重来），选择后续作执行。「继续上轮」即需要接管机制。

## Decision

### 1. 所有权转移，而非共享访问（用户裁决 2026-09-01）

接管是把一个未完成 GEO 操作的所有权从创建会话转移给当前会话的一次确认动作：CAS 抢占（同时仅一个赢家），可见性检查从「创建会话」改键为「当前所有者」，未批准投影从 approved-only 扩展为 owned-or-approved。原会话的降级不是新机器——所有权挪走后它自然落回已批准投影，最多补一句友好报错（「已被会话 X 接管」）。

### 2. 运行中不可接管（守卫）

唯一被挡的情形是「两个会话同时开着且旧的正在跑」，而这恰是唯一真正的双写冲突场景。常见路径（关掉旧窗口再开新的）由既有 pause-running-on-exit 保证 operation 已处暂停态，天然可接管。

### 3. 元信息默认可见、正文接管后可见（用户裁决 2026-09-01）

品牌状态摘要扩展含跨会话未完成 operation 的元信息（类型、卡在哪一步、待审数量、所属会话、时间），不含草稿正文与任何会话聊天记录——「草稿不跨会话泄露」的隔离原则保留在正文层，只在元信息层开口。

### 4. 接管确认复用信息闸门卡片

整卡一次确认，不产生第二确认入口；所有权变更留痕（谁、何时）。

### 5. 起点推导在提示词层，步骤序列不可改写（用户裁决 2026-09-01）

agent 读摘要后给出带理由的推荐起点与备选项，交计划确认门（plan-ack）裁决；推导只决定从哪个阶段/切片开始，不改写 18+1 步序列与确认门位置。智能只放入口；与 ADR-0009「纪律类规则改构造保证」同哲学——确定性状态机保证闸门不被跳过、恢复语义成立。

## Considered Options

- **共享读写（两会话都可操作未完成工作）**：否决——正是 session 私有设计当初要防的并发写冲突，接管模型以「同一时刻单一所有者」保留该动机。
- **接管即作废旧会话全部进行中状态**：否决——丢工作。
- **只读元信息、永远不可接管**：否决——知道了做不了，治标不治本。
- **LLM 自由编排步骤序列（过程智能）**：否决——确认门可能被绕过；checkpoint 恢复依赖固定步骤序列；聊天进度卡与工作台无法展示每次不同的流程；测试不可复现。入口智能 + 中间确定是既定边界。

## Consequences

- geo_operations spec 的 session 私有条款随本 ADR 修订为所有权语义：未批准状态属于当前所有者会话，可经确认门接管转移。
- 改动面：品牌状态摘要扩展（server 工具层 + Rust 检视端点）、接管 mutation（Rust store + server 服务 + MCP 工具）、可见性改键（文章与操作的 session 检查）、系统提示词升级（「先读后问」细化为「带推荐选项问」）。
- 术语已入 CONTEXT.md：「接管（Takeover）」「起点推导（Starting-Point Derivation）」。
