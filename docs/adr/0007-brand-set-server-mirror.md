# 品牌集服务端镜像：客户端全量快照上报

品牌工作区（BrandWorkspace）是纯客户端事实（Tauri 本地持久化），后端此前完全不感知。运营台重建要求账号列表展示「品牌集」，决定把品牌工作区名称镜像到后端：客户端在品牌增删改名后、登录后、启动时向 `PUT /auth/me/brands` 上报 `[{workspaceId, name}]` 全量快照，后端在同一事务内整组替换 `account_brands` 行；客户端是唯一权威，运营台只读展示 chips。

## Considered Options

- **运营手动标签**（建号/详情页手填品牌）：被否——人维护必然失真，且与客户端真实品牌脱节；运营台的内测量级撑不起这份重复劳动。若日后账号量暴增且客户端改动不可行，可再议。
- **事件增量同步**（create/rename/delete 各发事件）：被否——需要乱序、重放与补偿语义；品牌量级小（每账号 ≤100），全量快照开销可忽略，替换式写入天然幂等，协议最小。
- **后端从现有数据派生**（发布订单、上传内容里猜品牌名）：被否——后端所有载荷中没有结构化的品牌标识，无可派生源。

## Consequences

- 新增 `account_brands(account_id, workspace_id, name)` 表与 `PUT /auth/me/brands` 端点（requireAccountAuth；停用账号同步被 403 拦截，品牌集冻结在最后状态）。
- 客户端新增品牌上报调用：fire-and-forget，失败等下次触发自然补报；多设备同账号后写覆盖。
- 品牌名首次进入服务端存储：`docs/compliance/隐私政策.md` 需补「品牌工作区名称同步至运营后台」的说明。
- 运营台品牌集只读：纠错只能请客户在客户端改名（单权威原则，运营台不做第二写入口）。
