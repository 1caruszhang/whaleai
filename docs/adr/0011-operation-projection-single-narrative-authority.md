# 操作投影作为唯一叙事权威：显示与行动同源

## Context

2026-09-01 一轮「从问题选择到发布」的实际体验暴露出四类互相纠缠的缺陷：用户放行知识门后长时间无任何反馈，思考流里充满「等等」「让我想想」式的反复推敲；进度卡状态行同时显示「待开始」「1/7 道闸门」「当前：确认品牌知识变更」三个互相矛盾的信号（操作早已开始、知识门远未停靠）；问题池命中复用时渲染出页脚写着「确认后进入下一阶段」却没有任何按钮的死卡；goal 自由文本写「从问题选择开始」而结构跨度实为知识起步（7 道门含知识门），两张皮无人调和。

共同根因：GeoOperation 状态机是权威，但没有任何消费方直接读它——UI 从确认门**顺序**启发式推导「当前门」（不管该门是否真处 awaiting-confirmation），把放行后的 `ready` 一律译成「待开始」；agent 侧的决策回执 reminder 只是收据，每过一道门都要在约四千字策略提示词下重走「解析信封 → 重读计划 → 步骤标题映射工具 → 推导参数 → 现场权衡复用还是跳过」的完整推导链；复用语义只活在工具描述的一句话里，与计划步骤序列形成模型必须现场裁决的两难。

## Decision

### 1. 展示从投影派生，不做门序启发式

状态行与进度条只依据 `steps[].status` 如实派生：只有某道门的步骤真处 `awaiting-confirmation` 才报「待确认 · N/M 道闸门 · 当前：…」；工作步骤 armed（`ready`）或 `running` 时优先报正在推进的工作步骤（「正在推进：<步骤名>」，running 且有量化进度沿用「生成文章 3/5」）；操作 status 为 `ready` 但已放行过至少一道门或有步骤完成/跳过/运行时，状态词报「进行中」而非「待开始」。放行后的静默窗口由此获得诚实表达，无需为此补 started 里程碑。

### 2. 门间交接确定化：信封引述 next-step，模型从推导者降为执行者

五类决策回执信封扩展携带 `<next-step>`（工具名 + 一句话指引），由 shared 单表（与里程碑表同址维护）从**持久化计划**引述，随信封已有的 revision 防过期；保留「先重读对应 owner 再执行」指令。信封仍是收据不是新权威——next-step 是计划的引述，不是第二决策源。并发推进导致引述过期时，模型重读后自然校正，工具端的 revision CAS/幂等兜底误执行。

### 3. 问题池复用契约化，消除「生成还是跳过」两难

同知识版本已存在有效确认池时，`run_question_pool` 的调用零消耗秒回复用结果；该契约在工具描述、结果信封（`outcome` + proceed 提示）与 next-step 表三处以同一话术写明。模型按计划调用即安全，不再需要判断是否跳过。复用命中时确认卡呈现「已复用此前确认的题库，无需再次确认」，不显示「确认后进入下一阶段」的待决话术。

### 4. 计划卡头显示结构派生跨度

完整进度卡头部展示从结构派生的跨度标签（首个工作步骤 capability 映射的阶段名 → 终点阶段名，如「跨度：品牌知识 → 发布」）。goal 短语不再是跨度的唯一叙事；措辞与结构矛盾时用户立刻可见，不依赖模型措辞自律。

### 5. goal 措辞纪律入提示词

goal 必须与结构跨度一致：起点为知识链路时不得写「从问题选择开始」类措辞；起止选择如实经 `startingPointReason`/`endingPhase` 进入认可门文案。与 Decision 4 互为防线（结构标签兜底展示，措辞纪律收敛源头）。

## Considered Options

- **服务端缺省 targetRegion**：否决——地理边界策略（声明口径原样、门店兜底、全国转 geo-free）目前由模型按工具描述执行，服务端整套复刻错一处即静默挖错地域，属语义级损害。替代为增量校验：声明口径存在时 targetRegion 越界 fail-loud，口径缺失不拦截。
- **Rust 状态机动态跳步（产物已存在时跳过计划步骤）**：否决——把 plan × artifact 状态耦合进 `advance_operation`，波及全部意图与接管/checkpoint 语义；Decision 3 的契约化以零状态机改动达到同效。
- **补知识链 started 里程碑**：否决——Decision 1 的 armed 步骤展示已让空窗对用户不可见，不值得为此动里程碑的 begin/complete 配对语义。
- **提示词大瘦身**：延后——Decision 2 落地后最大纠结簇（复用两难）已确定化，剩余收益不确定，不值得在本次冒回归风险。
- **信封携带完整执行指令（构成新权威）**：否决——破坏「Reminder 不是持久化 authority」的既有边界；只引述、不裁决。

## Consequences

- `system_reminder_protocol.md`（信封契约扩展）、`geo_operations.md`（状态行派生规则与跨度标签）、`system_prompt_architecture.md`（goal 措辞纪律）随本 ADR 修订。
- 改动面：渲染层（状态行派生、复用池卡页脚、跨度标签）零数据路径风险；协议层（shared next-step 单表、五类信封 builder、工具描述与结果信封、系统提示词一句）增量式，renderer 投影对信封新字段按现有解析规则天然忽略。
- 测试缝全部复用现有：渲染组件测试、systemReminder 单测、xiaojing-geo-tool 单测、agent-session 集成测试模式；无新缝。
- 固化旧误导文案的三处断言随 Decision 1 有意更新（行为变更非回归）。
- 落地分两批：批一为 Decision 1/3(展示侧)/4 的纯前端切片；批二为 Decision 2/3(协议侧)/5 与越界校验；每批独立可发布可回滚。
