# 统一文件入口与受限会话读取

聊天输入框是用户文件的唯一入口：拖入的文件成为**会话私有**的"会话附件"（图片直接进入对话内容，文档由主 Agent 通过受限读取工具按需装载：头部 10K 字符 + offset 分页 + 扩展白名单）。品牌材料不是第二个入口，而是会话附件经 Agent 判断、用户裁决后的**升级路径**（`import_pasted_material` → 知识候选 → 确认门）；已升级的附件不再回读原文件，模型查询品牌知识。

## Considered Options

- **发送时全量注入 prompt（js_ai 原语义）**：保证内容必达，但上下文成本不可控，多文件/大文件直接臃肿。被"纯工具 + 分页读取 + 逐轮一次性提醒"取代。
- **三个并列文件目录各持一词**（`attachments/`、`xiaojing_files/`、`materials/`）：语义重叠、用户动作与落点硬耦合。收敛为两个领域概念（会话附件 / 品牌材料），目录降为实现细节。
- **品牌级共享暂存目录**（`xiaojing_files/` 现状）：违反"未确认工作不跨会话共享"的 Session 隔离原则。会话附件移入 `xiaojing_files/<sessionId>/`，升级为品牌知识后才在品牌内共享。
- **给 Agent 通用文件读取工具**：工具面扩张违背第一版最小工具面。读取仅限当前会话的暂存目录。

## Consequences

- 读取内容不写 transcript；会话恢复后模型通过重读工具获取历史附件内容，文件即真相。
- 会话删除时该会话的暂存子目录随之清理（Rust 会话删除范围扩大）。
- 存量 `xiaojing_files/` 文件（无会话归属）对读取工具不可见，不迁移。
