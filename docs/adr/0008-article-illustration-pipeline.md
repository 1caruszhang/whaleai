# 文章配图走材料图片候选池：占位符进正文、发布期换址、模板内嵌 CSS

## Context

2026-08-31 复盘出两个独立但同链路的问题：

其一，「OSS 文章格式混乱」的真正根因不是 HTML 上传被转坏——生成链路本来就是内容与样式分离的（doubao 只吐纯 markdown，Rust `render_article_html` 用 pulldown-cmark 套模板），而是那个固定模板**零 CSS**，发布产物一直在用浏览器默认样式裸奔（行宽拉满、标题巨大、表格无样式）。

其二，品牌材料里的图片被整体浪费：docx/pptx/pdf 导入解析只取文字层，内嵌图片在 `parseOoxml`/pdfjs 文本抽取时直接丢弃（原始文件字节留存于本地材料库，可取回）；OSS 出口只有 `putHtml` 一种；生成 prompt 无任何配图约定。同时 markdown→HTML 会透传 `![]()` 语法、渲染端 Markdown img 组件现成，缺口集中在素材提取、图片出口与生成契约三处。

本 ADR 经三轮设计对谈收敛。用户总纲：图片用在合适的位置（语义判断，非规则可算）；候选取品牌材料侧（与文章同生命周期）；独立上传图片与文档内嵌图要去重。

## Decision

### 1. 配图候选池 = 材料图片（术语见 CONTEXT.md），内容指纹全局去重

候选来源两种：材料文件内嵌图片（本期 docx/pptx zip 直取 `word/media/*`、`ppt/media/*`）+ 作为品牌材料直接上传的图片文件（png/jpg/jpeg/webp/gif，导入时跳过文字抽取直接打标）。同一张图片（sha256 相同）跨来源只入池一次——覆盖「文档里已有、用户又单独传同一张」的场景。会话附件图片**不进池**（会话级资产与品牌文章生命周期不对齐，二期再议）。PDF 内嵌图提取显式延后（pdfjs 对象层 brittle、工作量大，见 Considered Options）。

### 2. 两段筛选：导入时视觉打标 + 生成时模型终审

导入时对每张候选图跑一次视觉打标：输出一句中文描述 + 类型分类（产品实拍/环境/人物/图表/截图/图标装饰），图标装饰类与小尺寸图不进候选池。生成时把候选清单（id + 描述 + 来源材料名）注入 prompt，由生成模型终审取舍——是否用、用几张、放哪。用户勾选界面延后，不阻塞。打标模型定为 `doubao-seed-2-0-lite-260428`（2026-08-31 spike 经生产网关 `/gw/ark` 实测：`image_url` 输入可用，对实拍图产出准确中文描述；模型即 keyword-search 同款，零新供应商）。注意 lite 对简单任务也产 `reasoning_content`，打标调用应尝试关闭 thinking 省时省钱（参数不被接受时去掉即可，不影响能力结论）。回退路径：deepseek-v4-pro 现有 image-block 通路（全仓库唯一代码验证过的吃图通路）。

### 3. 位置由生成模型定：markdown 图片语法占位符，密度 ≤3、宁缺毋滥

生成模型在正文中输出 `![说明](material-image://<图片id>)` 形态的占位图片语法；内容契约新增配图纪律：全文 ≤3 张、无合适位置零配图是合法结果（与竞品「宁缺毋滥」同哲学）。生成模型**只看候选清单文字，不看图片本体**——位置判断靠描述足够，不动生成模型与 token 预算。`parseGeneratedArticleBody` 的「禁止【】占位符」校验对图片语法放行（占位符是受控 uri scheme，不是文本逃逸）。发布渲染期把占位符替换为真实 OSS URL 后再上传。

### 4. OSS 图片出口：新增图片上传、公共读、格式白名单、独立路径 sha256 去重

`objectStorage` 接口从仅 `putHtml` 扩为 `putHtml` + `putImage`（网关重签与直连兜底两条路都补）。图片对象**公共读**——文章页需匿名加载，用户明示接受品牌材料图片由此变为公网可访问。格式白名单 png/jpg/gif/webp，emf/wmf/tiff 跳过不做转换（浏览器渲染不了，转换成本高收益低）。存储路径独立于文章（`images/` 层、按 sha256 命名去重），同一 logo 不随每篇文章重复上传；文章 HTML 引用绝对公网 URL，objectKey 的 hash 版本机制保证重发布即换版。

### 5. 发布模板内嵌固定 CSS，不做外链样式表

CSS 以 `<style>` 内嵌进 Rust 固定模板：单文件自包含（超级媒介下单预览不丢样式）、无外链缓存失效问题；样式迭代靠文章重新发布走版本。这是对「格式混乱」的正面修复——内容与样式分离的架构本来就在，补的只是缺失的样式层。

### 6. 批准预览升级为渲染态

批准卡从裸 `<pre>`/textarea 改为「预览 / 编辑源文」切换（默认预览，占位符经材料 content API 换 blob 渲染；编辑态保留现有 textarea，用户删占位符行即删图，不加新 UI）。工作台只读批准稿直接换渲染态。否则「图片出现在合适位置」在发布前无法验收。

## Considered Options

- **生成后按规则盲插（每 H2 一图）**：否决——位置是语义判断，图文错位风险高。
- **生成模型直接输出最终 URL 或直接产 HTML+样式**：否决——破坏既有内容/样式分离架构；占位符保发布期可换址、可校验、可去重重写。
- **生成模型直接看图（多模态生成）**：否决——动生成通路与 8K token 预算，描述清单已够位置判断。
- **外链 OSS 样式表**：否决——多一跳请求、缓存失效复杂，单文件原子性与 hash 版本键最搭。
- **PDF 内嵌图提取本期做**：否决——现有解析只走 getTextContent 文字层，对象级提取 brittle；docx/pptx zip 直取已覆盖主要场景。
- **emf/wmf/tiff 服务端转换**：否决——转换依赖重、收益低，白名单跳过。
- **生成时候选池为空走材料请求卡提醒补图**：延后——ADR-0005 机制现成，二期挂上即可。
- **材料库用户勾选筛图界面**：延后——不阻塞本期，打标+终审已可用。
- **聊天附件图片进候选池**：延后——会话级与品牌级生命周期不对齐，需先解决资产升级语义。

## Consequences

- CONTEXT.md 增词条「材料图片」；「品牌材料」词条语义不变（材料图片是其派生资产，非第二入口）。
- 改动面：Node 材料导入（图片提取 + 打标 + 材料卡扩展名白名单放行图片）、生成 prompt 契约与 `parseGeneratedArticleBody` 校验放行、Rust 发布模板（内嵌 CSS + 占位符替换）与图片 egress（putImage 公共读 + 独立路径）、批准卡与工作台预览渲染化。materials 侧需新增图片资产表（sha256 唯一键）。
- 风险登记：材料图片经 OSS 公网可访问（用户明示接受）；打标失败或候选池空的降级路径是零配图发布，不阻塞主链。
- 发布产物从「零样式裸奔」升级为固定排版样式；后续样式迭代只动模板一处。
