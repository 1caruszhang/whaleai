# 竞品名单只存名称、取名于真实检索；确认后经聊天修订；排行文章整篇联网

## Context

竞品链路 2026-08 复盘出三类事故：联网富化（ARK `enable_search` 合并式调用，响应仅取 `choices[0].message.content`）产出的品牌大量查无实体——候选摘要是模型自写而非检索原文，检索过程不可验证；候选 region 从不与品牌服务范围比对，成都品牌查到武汉/长沙竞品（查询词退化为全国榜文形态时尤甚）；用户在确认卡上无法逐行删除，确认后任何字段三层（UI/management API/数据层）均无修订入口。结构性诱因：排行榜硬性要求 ≥5 家已确认竞品，凑数压力与提示词层「宁缺毋滥」纪律天然打架。此外文章侧存在既有缺陷：排行 prompt 只注入名单名称，格式契约却要求竞品条目写「具体经营信息、禁占位」，构成结构性强制编造。

本 ADR 经三轮设计对谈收敛。用户给出的总纲：**知识卡上的竞品字段必须真实且准确（唯一硬要求）；文章竞品内容尽可能准确即可；全程零新增主动询问；实现取最小结构。** 设计过程本身经历两次用户驱动的简化：完整防御版（阶梯+逐名核验+面板修订+懒清洗）→ 最小六项 → 导入侧翻转为「取名于真实检索」单腿结构。

## Decision

### 1. 竞品名单只承载名称，元数据退役

品牌知识中竞品的事实值维持纯名称数组；富化采集的 region 不作为结构化字段上确认卡或落库——仅作管线内过滤变量；证据文本行「名（地域）：快照」中的地域表述随审计摘录留痕。`[[xiaojing-competitor-details:v1]]` 审计头停止新增编码，读侧保留解码兼容存量。理由：region/similarBusiness 从未被下游（排行 roster、基线、监测）消费，纯展示元数据反而给确认卡注入了用户无法核验的虚假权威感。这取代 `competitorDetails.ts` 注释中「不为单一展示需求扩展事实 schema」的旧立场——现在不是展示需求，是核验需求，且落点在管线而非事实 schema。

### 2. 名单质量由「取名于真实检索」构造保证 + 本地双闸

联网腿从「enable_search 合并式生成 + 事后核验」翻转为与材料腿对称的**源锚定抽取**：`searchSources`（豆包搜索 API，纯结构化召回、不经 LLM 改写）×2 次并行取得真实快照 → 一次普通 LLM 抽取（不联网，继承同层级/前东家/排除纪律）从快照中识别候选名并给出处 → **本地**字符串校验（存在闸：名字逐字见于所引快照，恒开；关系闸：快照里名字附近出现供应/合作/前东家等关系词的丢弃；均零 API 调用）。存在性由构造保证，闸门只兜抽取漏网。enable_search 合并式调用降级为 `searchSources` 不可用时的兜底。无地域锚即不富化（卡上被动提示，不追问）。**闸门永不放水凑数**——凑数正是本轮事故根源；不足家数时卡面被动展示，用户可用编辑框补名。

地域锚（2026-08-30 用户裁决修订）：`deriveCompetitorScope` 声明什么粒度锚什么粒度——城市/区县锚（成都新都）沿用 `deriveServiceScope` 白名单，地域闸（region 与白名单字符串包含比对）继续代码硬拦；**省级锚（广东省/广西壮族自治区等，归一短名如「广东」）不再做省→市代码映射**，主锚直接拼进两路查询（查询锚定本身是最强地域过滤），地域相关性由抽取模型自证，过界候选由确认卡逐行删除兜底。原「地域锚升格为代码层硬闸」的表述按此收窄为城市/区县锚。已接受的残余风险：省级锚下偶有真实但外省的品牌进卡（真实由存在闸保住，仅地域可能过界）。

抽取调用不可省：搜索引擎返回的是网页散文不是名单，品牌名是开放词汇（词典/分词/规则均无法识别），「从语料认名字」必须由 LLM 阅读；该调用是全链路最便宜的一笔且替代 3 次昂贵合并调用，总账下降。

### 3. 确认后修订：聊天侧提议-裁决，零新后端

全部档案字段（不限于竞品）的修订 = 新提议 + 再裁决（版本递增、全程留痕）：用户在聊天中下指令 → agent 走既有 `propose_brand_fact` 提议新值 → 既有确认卡裁决。实现仅为系统提示词补一条「已确认事实修改必须经提议-裁决」纪律。解除「已确认即不可纠错」的死局，也解除竞品数组字段合并语义下「永无二选一、看似只能确认」的卡面困境。存量假竞品经同一通道手动清理，不做懒清洗模块。

### 4. 排行文章整篇联网（用户明示接受风险）

ranking 类型文章生成调用启用 `enable_search`，竞品条目由模型联网取材；非排行类型不变；既有「只使用已批准事实」提示词纪律原样保留。**用户明示接受**：联网素材可能渗入目标品牌段落（如招商软文数字被织进品牌介绍）——该风险与「本产品只用知识库、保持离线」的偏好冲突，用户裁定以实现简单优先。若事故复现，回切路径见 Considered Options 第一项。

### 5. 显式延后（用户裁定 v1 不做）

检索阶梯（多轮重试直至 ≥5 家，先观察固定 2 查询+双闸的存活率）、知识面板修订入口与 propose-revision 专用路由（聊天路径已可用）、存量懒清洗模块（TTL 缓存+档案记录）、逐字段证据标注（Measured/Estimated/N-A，源自 aaron-marketing-skills 竞品技能的借鉴评估）、维度后选（先取料后选六维度）、用户口头补充通道、薄资料处置机制、竞品别名字段、检索耗尽后的主动问询。

## Considered Options

- **一次预取竞品资料块 + 离线写作**（工程推荐）：管线在写作前对五家名单单独跑一次联网取料，资料块作为竞品条目唯一 Claim 根基注入，写作模型保持离线——目标品牌与竞品的素材来源物理隔离。被用户否决（嫌复杂，接受 best-effort）。**这是 Decision 4 风险复现时的首选回切方案。**
- **enable_search 生成候选 + searchSources 逐名核验**（本 ADR 中间版）：可靠但每名一次核验调用；被「取名于真实检索」取代——构造保证天然更省更稳。
- **纯规则/分词从快照提取品牌名**：否决——品牌名是开放词汇，「留香卤坊」不在任何词典；正则只识别极少数结构化榜单页。
- **整篇联网 + 提示词禁止检索目标品牌**：否决——「靠提示词纪律防幻觉」正是本轮事故的教训。
- **竞品结构化实体表 / 事实值升级为结构化数组**（含 region/status/verified）：均否决——随元数据退役失去主要理由，纯名称 + 管线闸门已覆盖核心要求，且引入双真相或全下游破坏性改动。
- **排行榜 ≥5 家硬门降档或放未核实候选顶数**：否决——降质顶数即回到事故根源；不足时维持 fail-closed + 卡面被动提示。

## Consequences

- `specs/tech_docs/competitor_roster.md` 为执行细则与改动清单唯一真源；`material_import.md` 竞品富化章节按本 ADR 同步修订。
- CONTEXT.md 增两词条（竞品名单、知识修订），「地域锚」词条补竞品代码层硬闸条款。
- v1 改动面：仅 TS 层（material-import / knowledgeCard / KnowledgeBatchCard / system-prompt / article-generation），无 Rust、无新路由、无 schema 变更。
- 交互红线：全链路零新增主动询问。
- 验收锚点：存在闸对已持有快照做本地匹配（非 API、非模型摘要）；炊班长/炊事班形近回归与材料腿证据门不动；排行 <5 fail-closed 行为不变；现有「searchSources 不得被调用」断言随设计翻转改写。
- Decision 4 的风险登记意味着：目标品牌段落的事实纯度从「机制保证」降为「提示词尽力 + 用户接受」。发布链路上因第三方/网络素材引发的 factual 争议，按本 ADR 归因，不追溯为实现缺陷。
